# Review: device-settings-plan.md

Reviewer: plan reviewer persona (read-only, no device access, nothing committed). Repo HEAD c098ac5. Reviewed 2026-11-24. Repo text was treated as data.

## Verdict: GO WITH REQUIRED CHANGES

The plan is mostly accurate against the repo and the design is sound in shape (one service, one atomic file, restrict first loosen last, fixed TTL). Eight changes are required before wave 1 starts. Two are design holes (the early unit does not do what its justification says; the unlock flow lands on the wrong screen), two are plan-mechanics holes (waves 1 and 2 cannot compile or pass their gates as specified; two Phase 0 spikes need code that does not exist yet), and the rest are corrections to claims and missing risks.

## Required changes

1. **Section 4.4 Unit A, section 2 item 6, section 4.4 "single late unit" alternative, section 7.1 "keep sshd.socket enabled (do not touch)", section 13 Q6.** Unit A "never calls systemctl" and starts nothing, yet the two-unit choice is justified by "closes the ssh window before sshd.socket listens". As written it cannot close it: sshd.socket is enabled and starts at boot long before unit B stops it. Either add a mechanism or drop the justification. A workable mechanism: unit A writes `/run/thing-revived/ssh-off` when persisted ssh is off, and a drop-in on `sshd.socket` (next to the existing `10-thing-revived-limits.conf`) carries `After=thing-revived-device-settings.service` and `ConditionPathExists=!/run/thing-revived/ssh-off`. The controller must then also remove the flag before a runtime `systemctl start sshd.socket`, or the start is a silent no-op (same trap the spike found for adbd conditions). Add a checker rule for the drop-in. Also assert `sshd.service` (non-socket) is not enabled, otherwise ssh off is ineffective.

2. **Section 4.4 Unit A ordering and failure.** Unit A runs `controller-agent`, which loads `controller.toml` (deny_unknown_fields, exit 78). It is not ordered after `thing-revived-etc.service` (provision is, and says why), and a stale config makes A fail with nothing to repair `boot-role`; `superbird-usb-role.service` then applies a stale `host` and unit B fails the same way. Required: the boot apply subcommands must not depend on `Config::load` (compiled-in unit names and paths, or a tolerant partial parse), or A must be `After=thing-revived-etc.service` and exit 0 after a fail-safe write. State what A does on failure (it has no `OnFailure=`). Fail safe for A should be: write `boot-role` device.

3. **Section 8.1 `ds-unlock`, section 6 frontend bullet.** The existing unlock reaction (`accounts.js` `user_session`, unlocked branch) does `pop` then `push: LIST`, so unlocking from Device settings lands on the Users list, not back on Device settings. The locked reaction and the `not_unlocked` handler only act when `inSection(ctx)` (SECTION screens), so Device settings and USB mode screens never relock and `device_settings_error` with `not_unlocked` is unhandled. The `users-lock-now` row ("Lock admin session") has `activate: []` and gets its lock only from `onLeave`, which the plan deletes: it becomes a dead row unless it sends `user_lock_session` explicitly. Specify: a return target on the unlock screen (or a Device-settings-specific unlock), SECTION membership or a parallel reaction for the new screens, mapping `device_settings_error not_unlocked` to the same relock path, and the explicit lock send. Keep `clearForms` on leave (password fields) even though the lock goes.

4. **Section 10 waves 1 to 3, gates.** The controller crate cannot compile or pass `cargo test` in wave 1 or 2 as specified. T1 changes `config.rs` and `ports.rs` (removing `[usb_role]`, `[debug_access]`, `UsbRoleCtl`, `DebugAccessCtl`) and T2 removes old `command.rs`/`event.rs`/`wire_map.rs` variants while `router.rs`, `policy.rs`, the old services and adapters (T5, T9) still use them. T1's note says "T7 removes them", but T7 is the frontend task; it is T9. Required: make waves 1 and 2 additive (add the new types and fixtures, keep the old), and let T9 do all deletions, or run the controller tasks in one serialised sequence. State which crate-level gates apply per task.

5. **Section 10 and section 11, Phase 0 sequencing.** P0.6 ("break the apply binary") and P0.7 ("against the real binary") need the `apply-device-settings` subcommand, which T9 builds in wave 3, and P0.6 needs units A and B, drafted by T4 in wave 1. Wave 0 is declared first and gates wave 2. Required: either specify shell stubs for P0.6 and test P0.7 as unit tests (T1/T5), or move them after wave 3 and say G0 excludes them. Also give P0.5 the real image unit set as input (see fact 18), and specify the exact commands for P0.1 to P0.4 (they are reversible only if a second access path exists; name it).

6. **Section 10 ownership overlaps and gaps.** `controller/tests/wire_golden.rs` is owned by T2 (wave 1) and listed again under T9 (wave 3); pick one owner or split by function. `frontend/src/utils/types.js` (command builders at line 229, command name list at 139) is not under T3's `frontend/src/transport/**`; assign it. The recipe `thing-revived-device-apply` is T4's but the `IMAGE_INSTALL` line is in the bbappend T8 owns; say so and order T8 after T4 (already) with the exact line. T7 "`input-clock-view.test.js` if it covers the view" is not an assignment. `build/tools/check_unit_graph.sh` (T4) sits beside T8's `build/tools` files; list it explicitly.

7. **Section 4.4 Unit B `OnFailure=`, P0.4.** `OnFailure=` fires on any non-zero exit or timeout, including a partial failure after the user's persisted surfaces were already up (for example a failed `ssh stop`). It then force-starts usb-bind and the stock getty, silently overriding persisted adb and uart without persisting that. If persisted mode is host, `OnFailure=thing-revived-usb-bind.service` starts usb-bind in host role (behaviour unknown, P0.4) and can repeat the original failure. Required: B treats host mode and "ssh stop failed" as non-failures or logs and continues; the failsafe is a dedicated mode-aware unit or script, not the raw units; state that the fallback intentionally ignores persisted adb/uart and log it at WARN.

8. **Section 8.3 item 5, section 13 Q1, section 9 step 3.** The reflash exposure rests on the skill note while `docs/users.md:120` says burn-mode reflash "wipes the device" and line 105 says a factory reset wipes the whole data partition. Resolve this before sizing the risk (a P0 item: read the partition table / flash script, or reflash a test unit and check). Name factory reset as a recovery path in the security text. Reseed on image change should move from open question to the design, because it changes the seed file schema (T1, T4): bake an explicit image id into `device-seed.json` rather than depending on `/etc/os-release` `BUILD_ID`, which the plan never verified exists in this image.

## Other findings (not blocking, fix while editing)

- **Section 2 item 7, section 4.4 deadlock claim.** The claim is correct only for units ordered After unit B. `multi-user.target` is (it gains After on its wanted units), nothing the plan starts is. State the precise rule (B must not be Before= anything it starts, directly or through a target it is ordered Before) instead of the blanket sentence. Rule 5's list is fine but incomplete: also forbid `Before=multi-user.target` and `Before=sysinit.target`.
- **Section 2 item 8, section 7.1 "all four disabled".** `console=ttyAML0,115200n8` is on the kernel command line (extlinux.conf). systemd-getty-generator normally starts `serial-getty@ttyAML0.service` for the kernel console regardless of wants symlinks. UNVERIFIED on this image, but if true a "UART off" device already has a stock getty before B runs, and checker rule 2 ("no instance enabled") says nothing about the generator. Add a P0 read-only check (`systemctl status serial-getty@ttyAML0` on a build with no wants link; `/run/systemd/generator/`).
- **Boot timing.** With adbd and usb-bind no longer in the boot transaction, the NCM link and the console login now appear only after B runs (after basic.target plus usb-role). A hung B means no link for up to the 60 s timeout, then OnFailure. Say so, and consider `TimeoutStartSec=20`.
- **Section 4.1 and 4.2.** Persistence details are sound (temp, fsync, rename, directory fsync verified in `json_settings.rs`; 0600; `/var/lib/thing-revived` is 0700 via tmpfiles). Gaps: the `.corrupt` rename and the fail-safe rewrite also need a directory fsync; write the `/var` read-only case so that the loader never panics and reports `persist_failed` on every set (already stated), and test it with the P0.7 bind mount. The host-forces-adb-off invariant is covered on load, set and boot apply. Add: B must re-run the invariant on the value it is about to apply, not trust that A already did, since the file can change between A and B (direct tampering needs root, so this is defence in depth only).
- **Section 6.** The sweep thread interval is 10 s, so "refused at 30:00" holds server side (`require` is exact) but the `session_locked` notification can lag up to 10 s. Say so in the acceptance text. A websocket reconnect or a Chromium reload is a new connection and loses the session; the countdown is display only and must reset on `session_locked`. The `UserSession.expires_in_secs` is only sent at unlock; the countdown must not assume more events.
- **Section 8.1 layout.** USB mode has four toggle rows, three warning notes, a busy note, an ADB note and a pinned hint. Whether that fits 480 px without scroll is not checked; the e2e claim should be backed by the measured row height, or cut the notes to two.
- **Section 7.2 rule 4.** "unit A contains no `systemctl` call" is asserted on a unit file, which cannot contain it; the property lives in the binary. Replace with a `layering.rs` test that the early path never spawns `systemctl`.
- **Section 9 step 1.** The controller startup fallback apply (`/run/thing-revived/device-settings.applied`) races unit A only on a live patch, but it can also repair a file the early unit is writing. Gate it on the marker being absent and take the same file lock.
- **Section 3.3 `users-lock-now`.** A "Lock admin session" row already exists on the Users list, so Q8's "Lock now" is mostly a relocation.
- **Docs list (8.4).** Add `docs/users.md:105` and `:120` (data partition wipe wording), and `build/README.md` for the seed id.

## Answers to the ranked open questions

1. Reseed adb and uart on image change: **yes**, and promote it to the design (see change 8). Use an image id baked into the seed file, compare it to an id stored in the JSON, reseed adb and uart only, log it at WARN. Note it also re-enables adb on a flag-1 dev reflash, which is the intended dev behaviour. Resolve the burn-flash `/var` conflict first.
2. Drop the `confirm` echo: **yes**. The session check is the real control and the existing echo was a client-bug guard on a loopback socket. Record it as a decision in section 8.3.
3. Legacy `boot-role` host honoured on first boot unless ADB seed is 1: **yes**, matches today's behaviour. Applies only when no JSON exists.
4. Toast and pop to the Device settings root on expiry: **yes**, but it needs the reaction work in change 3.
5. Losing the Users idle lock: **acceptable**, follows from the spec. Keep the password-field clearing on leave and update `user-management-plan.md` section 10 and `docs/users.md:51`.
6. Two boot units: **yes only if change 1 is made**, otherwise the early unit buys nothing beyond a `boot-role` sync that unit B cannot do in time; in that case one early unit plus the sshd.socket condition drop-in is the whole design and unit B stays late.
7. External clients of `usb_role_*` and `debug_*`: **no evidence in the repo**; the frontend and the golden fixtures are the only consumers I found. The owner must confirm; delete without aliases if so.
8. Extras: **Lock now only**, and note it duplicates the existing Users-list row.
9. Refusing ssh off: **no refusal**, show a warning note. Kiosk terminal and UART remain, and refusal logic needs live link state the controller does not have.

## Residual risks the plan is honest about, and one it is not

Honest: persisted root adb and uart on prod, no auto disable, loss of the confirm echo, the badge as the only on-screen signal. Not covered: the burn-flash versus data-partition conflict (change 8), and that with reseed absent the persisted state survives a hardened reflash by design.
